# Phase 1 Findings

Everything else was established while building and testing the pipeline.

## What worked

- **Raw-then-normalized held up immediately.** During development, the parser's location logic changed twice; both times the fix was re-parse, not re-fetch. The pattern paid for itself before Phase 1 even ended.
- **Idempotency by natural key `(source, external_id)` is clean and testable.** Integration tests prove re-ingestion changes zero rows in `jobs`, `companies`, `locations`, and `job_snapshots` (raw responses accumulate by design).
- **The call-budget guard earned its place on day one.** A hard per-run cap (`--max-calls`, default 60) plus `--dry-run` means development iteration cannot burn the 1,000/month Adzuna free tier. Cost: ~10 lines of code.
- **Snapshot capture moved into Phase 1** (a deliberate deviation from the original plan): the 90-day accumulation success metric can only be met if the clock starts now. The snapshot *analysis* still waits for Phase 3.
- **Migrations tested in both directions** caught a real defect: Alembic autogenerate produced naive `timestamp` columns where the spec requires `timestamptz`. Fixed at the model level (`DateTime(timezone=True)`), regenerated, verified in `information_schema`.

## Data quality issues — established during pipeline construction

1. **Postgres NULL-distinctness in the locations unique constraint.** `('US','Virginia',NULL)` would silently duplicate under `ON CONFLICT` because Postgres treats NULLs as distinct. Worked around with select-then-insert (safe: single-writer ingestion); regression-tested.
2. **`salary_is_predicted` arrives as string `'0'`/`'1'`**, not boolean. Coerced explicitly; a naive `bool("0")` would have marked every salary as estimated.
3. **Adzuna's `area` array varies in depth** — country-only, state-only, and full four-level hierarchies all occur. The parser degrades gracefully (missing levels → NULL); metro assignment in Phase 2 must handle all depths.
4. **Postings without a company exist** and are stored with `company_id = NULL`. Decision: no "Unknown" placeholder row — aggregates must handle NULLs explicitly rather than having a fake company pollute rankings.
5. **Adzuna truncates long descriptions.** This caps skill-extraction recall in Phase 2 regardless of NLP quality. Mitigation options to evaluate: accept the ceiling, or follow `redirect_url` for full text (scope/ToS review first).

## Data quality issues — ⏳ verify against real data

The exploration notebook's observations cell tracks the full list; headline items to quantify on first live run:

- ⏳ Company-name duplication rate (distinct raw strings per true employer, top 20)
- ⏳ Staffing-agency share of postings (TekSystems / Robert Half / Insight Global pattern)
- ⏳ Salary disclosure rate, and estimated-vs-disclosed split
- ⏳ Suspected hourly-as-annual contamination: size of the `salary_min < $25k` bucket
- ⏳ Remote floor (title/display-name signal) vs. eyeballed description mentions
- ⏳ Cross-query overlap rate (how much the six queries return the same postings)
- ⏳ `posted_at` vs `first_seen_at` gap distribution (is Adzuna's `created` trustworthy?)

## Surprises

- **How early the interesting judgment calls arrived.** "Is a job with no company still a data point?", "Is `salary_is_predicted` data or metadata?", "What does a missing snapshot row *mean*?" — all surfaced before a single real row was ingested. The project guide's claim that analytics is mostly judgment under ambiguity is checking out ahead of schedule.
- **Autogenerated migrations are genuinely untrustworthy**, exactly as the milestone warned — the timezone defect would have shipped silently without the review step.

## What this means for Phase 2 priorities

1. **Company normalization first** — it corrupts the most analyses (top employers, hiring velocity, company-level anything).
2. **Salary quality flags second** — period contamination + estimate separation gate every salary conclusion.
3. **Skill extraction third** — start with high-precision regex for the top ~50 skills; spaCy patterns after a manual audit baseline exists.
4. **Remote detection upgrade fourth** — description-level signals; keep reporting the Phase 1 floor alongside for comparability.

Do not open Phase 2 until the ⏳ items above are quantified — they set the priorities' *ordering* with data instead of guesses.
